# Project Plan

## Project Title
**My Life Journey Through Music**

## Project Overview
This project creates a two-page personal website describing my journey as a musician and guitarist. It combines project management, documentation, HTML, CSS, GitHub, and GitHub Pages.

# Risk Analysis

## Risk 1: Time Management
**Description:** Balancing the final project with work, school, and personal responsibilities could reduce available project time.  
**Impact:** 4/5  
**Probability:** 5/5  
**Risk Score:** 20/25 — High  
**TAME Response:** Mitigate

I will break the project into smaller tasks, prioritize required features before optional improvements, and focus on minimum project requirements if time becomes limited.

## Risk 2: GitHub and Visual Studio Code
**Description:** Mistakes with file organization, commits, pushing changes, or GitHub Pages could affect the final project.  
**Impact:** 5/5  
**Probability:** 4/5  
**Risk Score:** 20/25 — High  
**TAME Response:** Mitigate

I will check the repository after major updates and test the live GitHub Pages website instead of assuming the local and published versions behave the same way.

## Risk 3: Scope Creep
**Description:** Because music is a major personal interest, it would be easy to add unnecessary pages, audio features, animations, or other ideas.  
**Impact:** 4/5  
**Probability:** 3/5  
**Risk Score:** 12/25 — Medium  
**TAME Response:** Avoid

I will follow the approved scope and keep the website to two pages using HTML and CSS. New ideas can be considered for a future version.

## Risk 4: Broken Links or File Paths
**Impact:** 4/5  
**Probability:** 3/5  
**Risk Score:** 12/25 — Medium  
**TAME Response:** Mitigate

I will test navigation links, image paths, stylesheet links, README links, and both pages through the live website.

## Risk 5: Inconsistent Website Design
**Impact:** 3/5  
**Probability:** 2/5  
**Risk Score:** 6/25 — Low  
**TAME Response:** Mitigate

Both pages will use the same external `style.css` file, and I will verify that colors, typography, navigation, spacing, and image styling remain consistent.

# Work Breakdown Structure

## Phase 1: Planning and Scope
- Review final project requirements.
- Review original scope and Week 7 peer feedback.
- Revise `scope.md`.
- Define measurable success criteria.
- Identify risks and create the Work Breakdown Structure.

## Phase 2: Content Preparation
- Organize the story of my musical journey.
- Select homepage and About page content.
- Select a personal image.
- Proofread website content.

## Phase 3: Website Development
- Finalize `index.html`.
- Create `about.html`.
- Add navigation between pages.
- Finalize `style.css` and link both pages to it.
- Add the selected image.
- Apply consistent typography, colors, spacing, and layout.

## Phase 4: Documentation
- Create a professional `README.md`.
- Add live website and documentation links.
- Complete `retrospective.md`.
- Verify all documentation is in `docs/`.

## Phase 5: Testing and Quality Review
- Test navigation in both directions.
- Verify both pages load `style.css`.
- Check text readability and responsive image sizing.
- Check the website on desktop and a smaller browser window.
- Check README links and repository organization.
- Test the live GitHub Pages website.

## Phase 6: Final Submission
- Confirm the repository is public.
- Confirm the live website works.
- Capture screenshots of both live pages.
- Copy required HTML, CSS, and README content into Canvas.
- Include the live website and repository URLs.
- ZIP all project files and upload the ZIP to Canvas.

## Plan Summary
The highest risks are time management and technical issues involving GitHub and Visual Studio Code. Breaking the project into smaller tasks and testing throughout development will help reduce these risks. Required functionality and documentation will be prioritized before optional design improvements.
